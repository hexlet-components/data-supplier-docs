# data-supplier-docs

Данные здесь синтетические. Бренды, модели, цены и контакты выдуманы, домены взяты из зарезервированных под примеры (`example.com`, `example.ru`), совпадения с настоящими компаниями и товарами случайны.

Документы поставщиков бытовой техники для учебного проекта Хекслета по генерации карточек товара. Наборов два. Стартовый лежит в корне репозитория, на нём проверяется каждый шаг проекта. Большой лежит в папке `supplier-docs/`, он нужен для прогона разбора на объёме и на приёмку не влияет.

## Стартовый набор

Шесть файлов в корне репозитория.

| Файл | Что это |
| --- | --- |
| `blender_passport.pdf` | Паспорт изделия с описанием и таблицами характеристик |
| `blender_kp.docx` | Коммерческое предложение с текстом, прайсом и контактами менеджера |
| `kettle_spec.xlsx` | Спецификация со строками «артикул → параметры» |
| `kettle_manual.pdf` | Паспорт изделия другого производителя |
| `boiler_scan.pdf` | Документ, полученный сканированием |
| `golden_cards.json` | Эталон для замера качества генерации |

Это документы «как есть», в каждом своя особенность, из-за которой наивный разбор даёт неверный результат. Какая именно, вы увидите, когда до неё дойдёте. Эталон `golden_cards.json` понадобится только на шаге про наблюдаемость и метрики, и до него его лучше не открывать, чтобы не подгонять генерацию под ответ.

Файлы кладутся в `data/` репозитория проекта и коммитятся. Автопроверка сверяет их содержимое побайтово, поэтому их не переименовывают и не пересохраняют.

```sh
git clone --depth 1 https://github.com/hexlet-components/data-supplier-docs.git
mkdir -p data
cp data-supplier-docs/*.pdf data-supplier-docs/*.docx data-supplier-docs/*.xlsx data-supplier-docs/*.json data/
rm -rf data-supplier-docs
```

Клонировать репозиторий прямо в `data/` не стоит. Вместе с документами туда приедет его папка `.git`, и git закоммитит ссылку на чужой репозиторий вместо файлов.

## Большой набор

Сто документов в папке `supplier-docs/`: паспорта изделий, спецификации и коммерческие предложения по десяти категориям товара. Документы однотипные и разбираются без подвохов. Набор сделан для проверки разбирающей программы на объёме, когда она уже работает на стартовых файлах и нужно увидеть, держится ли она на сотне.

Клоном, без истории:

```sh
git clone --depth 1 https://github.com/hexlet-components/data-supplier-docs.git
mv data-supplier-docs/supplier-docs data/bulk
rm -rf data-supplier-docs
```

Отдельная папка вроде `data/bulk/` держит стартовые документы на виду отдельно от песочницы.

Архивом, если git не нужен, кнопка **Code → Download ZIP** на странице репозитория или напрямую:

```sh
curl -L -o supplier-docs.zip https://github.com/hexlet-components/data-supplier-docs/archive/refs/heads/main.zip
```

Архив разворачивается в папку `data-supplier-docs-main/`, большой набор лежит в ней как `data-supplier-docs-main/supplier-docs/`, стартовый в самой папке.

### Что внутри

Десять категорий: вентиляторы, кофеварки, обогреватели, утюги, микроволновые печи, мультиварки, мясорубки, тостеры, пылесосы, аэрогрили. На каждую по десять файлов, итого сто.

| Тип документа | Сколько на категорию | Формат | Что внутри |
| --- | --- | --- | --- |
| Паспорт изделия | 5 | pdf | Описание модели, таблица характеристик, комплектация, правила эксплуатации, гарантия |
| Спецификация | 3 | xlsx | Таблица «артикул → параметры»: бренд, модель, мощность, вес, оптовая цена |
| Коммерческое предложение | 2 | pdf | Прайс-лист по линейке, условия отгрузки, контакты менеджера |

Имена файлов говорят сами за себя: `fan_passport_fan_40.pdf`, `coffee_spec_2.xlsx`, `vacuum_kp_1.pdf`.

### Свойства набора

- **Документы чистые.** Текстовый слой есть у каждого pdf, сканов нет, таблицы размечены таблицами. Разбор идёт стандартными библиотеками, обходных приёмов набор не требует.
- **Структура одна на все категории.** Паспорт вентилятора и паспорт мясорубки устроены одинаково, отличаются только названия характеристик. Программа, которая вытягивает артикул из одного паспорта, обязана вытянуть его из всех пятидесяти.
- **Сведения о модели размазаны по документам.** В спецификациях каждой категории девять артикулов, а паспортов пять. То есть на четыре модели из девяти полного описания нет, и карточка по ним собирается из спецификации и коммерческого предложения.
- **Линейка поделена между документами.** Три спецификации категории берут свой диапазон моделей, два коммерческих предложения делят линейку между собой. Один документ полной картины не даёт.

Ловушек в большом наборе нет, и в этом его назначение. Он показывает, держится ли разбор на всей линейке, и программа, заточенная под конкретный файл, разваливается здесь сразу. Документы с подвохами лежат в стартовом наборе.

## Проверка наборов

```sh
make test
```

Сверяет состав стартового набора, считает файлы большого, сверяет сетку «5 паспортов, 3 спецификации, 2 предложения» по каждой категории и проверяет текстовый слой у всех pdf большого набора. Нужна, когда наборы правят, потому что документ, пересохранённый без текстового слоя, снаружи выглядит целым. Нужен `pdftotext` из poppler-utils.

Стартовый набор побайтово совпадает с фикстурами проекта, по которым идёт автопроверка. Правка файла в корне без той же правки в проекте краснит проверку у каждого студента.
